# BanyanResearch（榕树）AC 项目定义

更新时间：2026-10-07。本文记录已确定的意图、限制、第一版实现边界及后续评估。A = Aim（意图 / 目标），C = Constraints（限制），Eval = Evaluation（评估）。用户已授权从文档讨论进入实现，并允许多个 Agent 并行完成模块。

## 当前交付范围

本地 MVP 已包含外部采集、博客同步、公开仓库清单与观点分析、研究问题管理、跨资料推荐、反馈、信息源编辑和任务状态页面。分析调用本机 Codex CLI 的独立非交互任务，不使用当前聊天会话。

这里描述实现范围，不代表推荐质量已完成个人使用验收，也不代表所有信息源均可成功采集。真实任务结果以网页记录为准；视觉验收状态不在本文中宣称完成。

## A：Aim 意图与目标

让系统了解我正在研究什么、实践什么，以及已有问题发生了哪些新进展。外部文章、自己的博客和代码作为不同类型的证据，形成可追溯的个人知识，并在网页上回答：**新信息是什么？它和我的哪些问题或实践有关？为什么值得我看？**

第一版的完整使用流程是：维护信息源和研究问题 → 更新博客及公开项目资料 → 采集外部文章并分析 → 展示带关联依据的推荐 → 人工反馈 → 后续分析参考反馈。允许没有现成个人关联、但技术价值明确的探索内容；目前未实现单独的探索配额或开关。

### 模块一：外部技术信息

- 来源类别为个人博客、公司 / 官方技术站、新闻媒体；内容领域覆盖 AI、游戏开发、服务端及其交叉方向。来源类别与内容主题分开保存。
- 首批 21 个来源来自公开资源清单和官方站点，后台支持新增、搜索筛选、编辑备注与 RSS / Atom 地址、启停。默认清单不覆盖后续人工编辑。
- 从已启用来源获取近期候选，进行 URL / 标题去重和分析。来源失败与无近期内容分别显示，不将启用状态当成采集成功。
- 数据库仅保存链接、标题、来源、主题、时间、Agent 短摘要、结构化问题 / 方法 / 结论、入选理由及关联对象；不持久保存外部文章正文或原文摘录。
- 技术主张应回到原始链接。来源知名度不等于每篇内容都可信，不能凭关键词相似度声称解决了用户的问题。

### 模块二：个人博客与研究问题

博客来源为 [dean-winston/dean-winston.github.io](https://github.com/dean-winston/dean-winston.github.io)，发布站点为 [Dean's Blog](https://dean-winston.github.io/)。从仓库同步符合文章元数据规则的 Markdown 全文，按文件版本识别新增和修改。首次同步覆盖当前可识别的历史文章，不追溯全部提交历史。

系统分析博客主题，提取候选研究问题。候选默认“暂时搁置”，保留出处并明确等待确认；用户可修改并设置为“正在研究”或“已解决”。只有活跃问题作为正在研究的问题参与匹配，避免将文章提到的所有术语自动当成个人意图。

推荐重点包括：当前研究方向的相关实践，以及旧问题的新候选方案。应说明具体联系并给出双方出处，由用户判断方案是否真正解决问题。推送先采用网页推荐列表，不发送邮件或即时消息。

### 模块三：工程实践与观点

目标账号为 [dean-winston](https://github.com/dean-winston)。第一版枚举账号下**全部公开仓库**，无需逐个指定。非 Fork 仓库按用户自己的项目处理；Fork 保留清单，不作为用户工程观点分析。私有仓库尚未接入。

一个仓库对应一张工程观点卡：

| 字段 | 目的 |
| --- | --- |
| 问题 / 目标 | 解释工程工作在解决什么 |
| 工程观点 | 说明代码表达或验证的主张 |
| 实际方法 | 概括实现方式 |
| 取舍 | 描述依据和限制，不能编造设计动机 |
| 验证情况 | 区分已存在的测试 / 记录与尚未验证的判断 |
| 推断标识 | 明确观点是系统推断还是有直接记录 |
| 证据链接 | 指向所分析提交版本的文档或代码文件 |
| 分析时间与提交版本 | 让观点时效性可见 |

当前读取选定文档与代码片段，受数量、长度和时间上限约束；不是穷尽整仓库的审计。Issue、Pull Request、完整提交演变及观点历史时间线尚未实现。仓库不持续监听，用户手动同步或重新分析；系统不修改仓库或向 GitHub 提交内容。分析失败时保留失败原因，已有卡片应明确属于之前的分析。

## C：Constraints 限制

### 已采用的第一版默认值

用户确认可以开始实现后，以下作为实现起点，可在后续使用中调整：

| 决策 | 默认行为 |
| --- | --- |
| 运行方式 | 本地单人服务，Node.js 22+；Codex CLI 安装并登录 |
| 自动更新 | 默认每日一次，仅在服务运行时检查到期任务；可关闭；不是精确时刻通知 |
| 外部历史窗口 | 最近 30 天，每来源最多 3 篇候选 |
| 文章分析预算 | 每轮最多 15 篇，后台可设置 1–100 |
| 项目分析预算 | 每轮最多 5 个非 Fork 仓库，后台可设置 1–20 |
| 博客历史范围 | 当前可识别的文章全文同步，修改后更新 |
| 仓库范围与触发 | 全部公开仓库清单；手动分析当前版本；私有仓库另定 |
| 推荐送达 | 网页列表，提供未处理 / 有用 / 不相关 / 已了解 / 稍后看状态 |
| 问题维护 | 用户手动添加，或确认 Agent 提取的候选；活跃 / 搁置 / 已解决 |
| 分析超时 | 单次默认 150 秒，可通过环境变量调整 |
| 中断恢复 | 服务重启后未完成任务标为中断，允许手动重跑 |

有限预算意味着一次任务不保证分析所有来源的全部文章或全部仓库。首次项目分析可分多轮完成。任务页面显示执行状态和失败；不会用虚构数据填补失败结果。

### 数据与权限

- 外部自动采集仅持久保存派生元数据，不保存外部正文或摘录；用户自己的博客可全文入库。
- 仓库保存观点卡、版本及证据链接，不持久保存读取的代码正文。
- 旧有“知识库”手动记录 / 文件夹导入继续可用，属于用户主动提供资料的入口，与自动外部采集的存储边界分开。
- Codex 使用独立临时目录、临时会话、结构化输出与只读执行限制，并关闭相应工具能力；提示要求不执行资料中的指令。分析失败或证据不足应如实说明。
- 模型仍需处理提交给它的材料。本地存储规则不等于对 Codex 或模型服务运行记录、第三方数据保留作绝对承诺。
- 当前只处理公开博客和公开仓库；私有内容授权与模型处理边界在接入前决定。
- 反馈保留并供后续匹配参考；没有实现完整的人工作品版本审计或所有观点的历史回滚。

### 部署

第一版在本机运行，数据为本地 JSON、任务队列和调度在进程内。执行入口已封装为 `runStructured`，已实现本地 Codex CLI 和独立 OpenAI API 两种适配器。

最终必须部署到 Serverless 云环境并完全脱离个人电脑。当前已实现 Cloudflare Workers API / 静态页面、D1 持久存储、Workflows 任务步骤、每小时 Cron 和密码登录；账号已完成 OAuth 授权，D1 已创建并迁移 96 条实体记录，数据库 ID 已配置；站点已发布，基础线上验收通过。模型仍未配置，持续助手关闭，模型与预算待确定。云端使用独立模型 API（支持 OpenAI 与 DeepSeek），禁止依赖本机 CLI。部署与实际账号联调验收仍待完成。

## Eval：评估与验收

先评估真实流程的可用性、证据准确性，再由实际反馈设置推荐质量指标。

| 验收场景 | 观察标准 |
| --- | --- |
| 维护信息源 | 编辑备注、订阅和启停状态后刷新 / 重启保留；无效或重复 URL 被拒绝 |
| 外部采集 | 仅启用来源参与；重复内容不重复入库；失败与无内容区分；持久文件不含外部正文 / 摘录 |
| 博客同步 | 全文可读、出处可追溯；未修改内容不重复分析；新增 / 修改可识别 |
| 仓库归属 | 全部公开仓库入清单；Fork 不误认为个人工程观点 |
| 工程观点 | 证据指向正确版本；推断与事实区分；不存在的测试结果不得虚构 |
| 研究问题 | 候选不自动当成活跃问题；修改和状态变化持久保存 |
| 关联推荐 | 解释对应的博客、问题或项目；关键词相似但无实际联系不能强行关联 |
| 推荐反馈 | 状态可保存、撤销并被后续分析参考；重分析保留人工反馈 |
| 失败与恢复 | 模型或站点失败可见；任务不伪装成功；重启中断记录清楚 |
| 未来云端 | 个人电脑关机或断网后仍能完成采集、分析与展示 |

代码测试、真实接口运行和网页视觉检查是不同层次的验收，不互相替代。建议用户用自己的博客与熟悉仓库核对首批结果，提供“值得推荐、无关、误判、遗漏”样例，逐步判断有用率和噪音；当前尚未设定可承诺的准确率。

## 2026-10-07：云端与持续助手实现补充

用户要求部署到 Serverless，并让助手持续运行。现已加入 Cloudflare Workers + D1 + Workflows 的实现和配置，并已发布站点，实际线上登录与数据验收已通过。具体部署命令、数据库配置、迁移和 secrets 设置见 README。

持续助手默认总开关关闭。研究和写作助手分别保存目标、状态、工作记忆、上次行动及理由、下次计划时间；每轮进行“判断 → 执行动作或等待 → 保存结果”。工程助手始终手动触发，遵守不自动监听仓库的既有要求。

默认设置为最少间隔 24 小时、两个自动助手共享每日 3 次决策 / 6 次行动，按 UTC 日期更新计数。Cron 每小时检查到期情况；不是精确时间的提醒。状态和次数持久化到 D1，不能通过进程重启清空计数。页面支持角色启停、修改目标、查看记忆和事件以及手动唤醒。

这些上限限制运行次数，**不是金额硬预算**。一个动作可能产生多次模型调用，模型与云基础设施分别收费。开启前仍需确定模型、费用预期和供应商侧费用控制；没有实现按实际账单金额自动停机。旧每日调度在云端默认关闭，避免和持续助手重复执行。

云端通过访问密码建立 HttpOnly Cookie 会话，不保存明文密码到浏览器存储。云端不能读取本机文件夹，目录导入入口禁用；本地历史资料不会自动迁移；本轮已通过空库导入迁移 96 条实体记录。云端密钥、模型服务的数据处理规则与真实运行费用，需要部署时明确。

新增验收：未配置模型时不能伪装可运行；总开关和角色暂停有效；工程助手不自动执行仓库动作；重复工作流不重复执行已完成步骤；次数预算与记忆能跨进程恢复；云端电脑离线后能持续运行。构建和单元测试通过不代表这些云端真实环境验收已完成。
